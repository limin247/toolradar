工具雷达TOOLRADAR
快照 —

别问「有什么好工具」，
先说你今天要干什么。

同一个仓库，对做前端的人是神器，对做运维的人是噪音。所以这里的榜单按工作场景切分， 再叠一层时间口径：总榜看存量，周榜看谁刚冒头，活跃榜看谁还在维护。

    这个组合下没有工具

    上升榜需要两次快照

    「上升」= 同一个仓库在两个快照之间的 Δ stars。GitHub 的搜索 API 不返回增量，所以这个榜只能靠自己的历史快照算。仓库里已经带了抓取脚本：

    node scripts/fetch-github.mjs   # 每天跑一次
node scripts/build-data.mjs     # 自动对比最近两个快照

    跑满两天后，这个榜会显示真实的名次变化，而不是一个猜出来的「热度分」。

    榜单口径与设计取舍

    榜单口径

    • 星标总榜：快照时点的 stargazers 数，全站存量。
    • 本周新星：最近 7 天创建的仓库按星数排。这是「谁刚冒头」，不是 GitHub Trending 的周增速。
    • 本月新星：最近 30 天创建的同口径。
    • 活跃榜：最近 7 天有 push 的仓库按星数排，回答「谁还在维护」。
    • 上升榜：需要两次快照，见上方说明。

    三条刻意的取舍

    • 场景先于语言。按 TypeScript/Python 分类等于没分类——同一个后端可能用三种语言。
    • 不算「热度分」。没有数据支撑的加权分数只是把猜测包装成排序。宁可少一个榜。
    • 原文不删。中文定位是编辑判断，仓库的原始描述一并保留，你可以自己核对。

    数据来自哪里

    • GitHub 搜索 API（/search/repositories），17 组查询，去重后 1475 个仓库。
    • 其中 253 个做了人工策展（场景、中文定位、选型建议），其余保留原厂描述，标「原厂描述」。
    • 页面无框架、无构建、无外链字体——双击 index.html 就能开。
    数据快照 — · 由 scripts/fetch-github.mjs 生成 星数会变，结论会过时。请以你打开它的那天为准。
